# Бот Бандит — Complete

Готовая база для VK-игры в стиле текстовой экономической RPG.

## Включено

- VK Long Poll;
- SQLite + WAL;
- регистрация;
- профиль;
- 4 работы и cooldown;
- XP/уровни;
- бизнес «Контрабандистский аэропорт»;
- реальный склад сырья;
- фоновый тик бизнеса раз в 60 секунд;
- catch-up бизнеса после перезапуска;
- реферальная система;
- переводы;
- скам/ограбление;
- автосалон;
- гараж;
- продажа машин;
- магазин;
- продажа вещей;
- казино;
- рейтинг;
- админ-команды;
- журнал экономических операций.

## Запуск

Требуется Python 3.10+.

```bash
python -m pip install -r requirements.txt
```

Создай `.env` на основе `.env.example`:

```env
VK_TOKEN=токен_сообщества
GROUP_ID=ID_сообщества
OWNER_VK_ID=твой_VK_ID
ADMIN_IDS=
DB_PATH=bandit.db
```

Запуск локально:

```bash
python run.py
```

`run.py` подключает игровые улучшения и исправления ввода телефона перед запуском VK Long Poll. На VPS используй настроенную systemd-службу, а не запускай второй экземпляр вручную.

## Экономика

Бизнес стоит $100 000 000.

Сырьё:
- 1 единица = $40 000;
- 1 минута работы = 1 единица сырья;
- 1 минута приносит $40 000;
- максимальный склад = 5 000 000.

Бизнес тикает в отдельном фоне раз в минуту. Дополнительно `last_tick` позволяет восстановить пропущенное время после перезапуска.

## Резервная копия

Перед обновлением на Linux останови службу, создай резервную копию базы и только потом заменяй файлы:

```bash
sudo systemctl stop bandit-city
cp -a bandit.db "bandit.db.backup.$(date +%Y%m%d-%H%M%S)"
```

Архив релиза не содержит `.env`, `bandit.db`, каталога `.github`, тестов и виртуального окружения. При ручной установке распаковывай исходники поверх проекта, не удаляя существующие конфигурацию и базу. После замены проверь синтаксис, запусти `selftest.py` в изолированном окружении/тестовой базе, затем запусти службу и проверь `journalctl -u bandit-city -n 100 --no-pager`.

## Безопасность

Не публикуй `.env` и токен сообщества. Не добавляй `.env` в Git.

Для большой аудитории рекомендуется перейти с SQLite на PostgreSQL и вынести фоновые задачи в отдельный worker.

## Иерархия ролей

- 👤 **PLAYER** — обычный игрок.
- 🛡 **MODERATOR** — модерация игроков, блокировки и журнал.
- ⚙️ **ADMIN** — игровые системы, экономика, XP, бизнес, машины, вещи, промокоды, рассылка, ивенты и техрежим.
- 👑 **OWNER** — полный доступ и управление персоналом.

Владелец задаётся переменной окружения `OWNER_VK_ID`. Указывай здесь только свой VK ID. Переменная `ADMIN_IDS` предназначена только для будущих заместителей; пока никого не назначено, оставь её пустой. Значения `.env` не хранятся в репозитории и не выводятся в логи. При запуске настроенный владелец становится единственным `OWNER`; старые конфликтующие OWNER-роли понижаются, а идентификаторы из `ADMIN_IDS` получают роль `ADMIN`.

Пример на VPS:

```env
OWNER_VK_ID=твой_VK_ID
```

После изменения `.env` сервис необходимо перезапустить. Не добавляй ID владельца в `ADMIN_IDS`: он задаётся только через `OWNER_VK_ID`.


## Автоматическое объявление релизов

При запуске бот читает `RELEASE.txt`. Если поле `Build` отличается от релиза, который уже обработан в базе данных, бот автоматически объявляет обновление игрокам, для которых разрешены сообщения сообщества.

- Каждое объявление привязано к уникальному значению `Build`.
- Прогресс сохраняется в SQLite, поэтому перезапуск не рассылает уже доставленные сообщения повторно.
- Если отправка временно не удалась, бот сохраняет ошибку и попробует продолжить рассылку при следующем запуске.
- Чтобы объявить следующую версию, обнови `Build` и строку `Announcement` в `RELEASE.txt`.
- На VPS не нужны GitHub Actions. При ручном обновлении сохраняй существующие `.env` и `bandit.db`.

Встроенная рассылка использует список зарегистрированных игроков без блокировок; игроки, запретившие сообщения сообщества, пропускаются.


## Создание промокодов в админке

В панели открой **🎟 Промокоды → ➕ Создать промокод** и отправь строку в формате:

`CODE|TITLE|CASH|XP|MAX_USES`

Пример кода с точкой: `0.20|Подарок 0.20|20000|100|0`.

- `CODE` — латинские/русские буквы, цифры, точка, дефис или подчёркивание; например `0.20` или `ZEROSHKA20`.
- `CASH` и `XP` — целые неотрицательные числа.
- `MAX_USES=0` — без общего лимита; иначе указывается число активаций.
- Для выдачи предмета/машины добавь два поля: `|ITEM|SLOT`, например `|turismo|car`.
- Уже существующий код не перезаписывается, чтобы не обнулять счётчик использований.
- Старые базы автоматически дополняются недостающими колонками промокодов без сброса данных игроков.
